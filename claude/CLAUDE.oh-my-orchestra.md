## 작업 원칙
- "수정해줘", "개발해줘" 등 명확한 지시가 없으면 코드는 건드리지 말고 분석/확인만 할 것

## 코드 스타일
- 들여쓰기는 스페이스 4칸
- 코드 컨벤션은 기존 소스 스타일과 유사하게 맞출 것

## 스킬
- 화면(프론트엔드 UI) 개발 시에는 항상 `design-taste-frontend` 스킬을 먼저 호출할 것
- 화면(프론트엔드 UI) 개발 시에는 항상 `ui-ux-pro-max:ui-ux-pro-max` 스킬도 함께 호출할 것
- 사이트 URL 검사 요청 시에는 `npx impeccable detect <URL>` 명령을 실행할 것

# Communication
- 장황한 설명보다 결론을 먼저 말한다.
- 사용자에게 보이는 모든 텍스트는 한국어로 쓴다. 도구 호출 사이의 진행 문구, 작업 끝 요약 박스(recap·질문·버튼 문구), 최종 요약, 표, 제목 모두 해당한다. 코드 식별자·파일명·기술 용어만 원문을 유지한다. 작업이 길어져도 영어로 돌아가지 않는다.
- 요구사항 정의서와 RTM은 사용자가 요청할 때만 작성한다.

# Behavior Principles (Karpathy에서 영감받은 4원칙)
- 가정하지 말고, 혼란을 숨기지 말고, 트레이드오프를 표면화하라.
  모호하면 코드를 쓰기 전에 먼저 질문한다.
- 문제를 푸는 최소한만 구현한다. 투기적 추상화·미래 대비 설계는 금지.
- 요청받은 것만 건드린다. 관련 없는 리팩터·rename·포맷팅은 하지 않는다.
- 검증 가능한 목표를 세우고, 그 목표가 통과할 때까지 스스로 루프한다.
